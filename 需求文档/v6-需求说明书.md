## 1. 目标
- 已经开户的商户，可以用 **USDT-TRC20** 收款（充币）和付款（提币）。
- 有开发能力的商户用**开放 API**，没有开发能力的商户用**商户后台**，两者功能对应。
- **系统不保存任何私钥**：归集和提币都由 Amos 在自己的浏览器里签名。
- 按 **50 个商户以内、每天 10,000 笔以内**设计。
- 朋友使用期间跑在 Vercel 免费版上；成熟后迁移到阿里云或 AWS，处理牌照，再对外开放（本版不做）。

## 2. 使用者
| 角色 | 做什么 |
|---|---|
| 商户（授权联系人） | 登录商户后台；管理客户、创建订单、手动匹配；查看交易和余额；发起提币；管理 API 密钥、回调地址、IP 白名单 |
| 商户的系统（开发人员） | 调用开放 API；接收回调 |
| 付款方（商户的客户） | 打开付款页面，或者直接往分配给他的固定地址转账，**不需要登录** |
| Amos（运营） | 管理商户和手续费；手动归集；审核并签名提币；处理异常到账；查看对账 |

## 3. 按客户收款（v6.1 修改）
> v6.1 把原来的"订单收款"和"无订单收款"合并成一种方式：**每个客户一个永久地址，订单可选**。转到客户地址的钱都算这个客户的；开启订单模式的商户，系统在到账和订单之间自动双向匹配。

```mermaid
flowchart LR
    C["商户的客户<br/>customer_id"] --- ADDR["这个客户的永久地址<br/>（一个客户一个）"]
    ADDR -->|"付款方转账"| D["到账<br/>扣除收款费后计入商户余额<br/>发到账通知（带 customer_id）"]
    D --> M{"订单模式开启？"}
    M -->|"否"| END1["结束"]
    M -->|"是"| MATCH["和这个客户的订单双向匹配<br/>（§3.3）"]
    O["商户创建订单<br/>（后台或 API，customer_id 必填）"] --> MATCH
    MATCH --> CB["订单匹配通知"]
```

### 3.1 客户
| 项目 | 规则 |
|---|---|
| 客户标识 `customer_id` | **由商户自己定**，在同一个商户下唯一，1 到 128 位（字母、数字、`_ - . @`），例如商户系统里的用户编号或邮箱。**创建后不能修改** |
| 选填信息 | 名称、邮箱、备注。只用于显示和搜索，商户可以修改。邮箱加密保存 |
| 怎么产生 | 第一次在订单、申请地址或代付里出现某个 `customer_id` 时自动创建；商户也可以在后台手动新建 |
| 余额 | **客户没有余额**，余额只属于商户。客户这一层用来归属、统计和对账 |
| 不做 | 合并两个客户 |

### 3.2 客户地址
- **每个客户一个收款地址，永久分配，永不收回，也不会转给其他客户或其他商户。**
- 地址不区分"空闲"或"占用"：同一个客户的所有订单、所有付款都用这一个地址。
- **只要有钱转进这个地址，就是这个客户的钱**：19 个确认后，扣除收款费，计入商户余额，并发到账通知（带 `customer_id`）。
- 低于 1 USDT 的到账：不入账、不参与匹配、不发通知，只记录（防止垃圾转账）。
- 地址由 Amos 初始化时提供的公钥（xpub）推导，系统本身无法动用地址里的钱。

### 3.3 订单模式与双向匹配
**订单模式由 Amos 在运营后台为每个商户单独开启并设置**（商户在自己的后台只能查看）：

| 设置 | 默认 | 可填范围 | 说明 |
|---|---|---|---|
| 订单模式 | 开启 | 开启 / 关闭 | 关闭时，商户不能创建订单（API 返回 403），到账只按客户记录 |
| 匹配下限 L | 90% | 1% 到 100% | 匹配到的到账累计达到订单金额的 L，订单就算匹配成功 |
| 匹配上限 H | 110% | 100% 到 1000% | 累计金额超过订单金额的 H，算"超额付款" |
| 订单过期时间 | 30 分钟 | 5 分钟到 24 小时 | 所有订单统一使用，创建订单时不再单独传 |
| 先到账后建单的回看时间 | 24 小时 | 0 到 72 小时 | 新建订单时，只匹配这段时间内的未匹配到账；0 表示不做这个方向的匹配 |

**匹配规则（只在同一个商户的同一个客户内部匹配；匹配只给到账"贴上订单号"，不影响余额）：**

```mermaid
flowchart TB
    subgraph A["方向一：先有订单，后到账"]
        A1["到账"] --> A2{"这个客户有<br/>未过期、未完成的订单？"}
        A2 -->|"没有"| A3["记为未匹配的到账"]
        A2 -->|"有"| A4["选订单：优先选加上这笔后累计落在 L 到 H 之间的；<br/>都不满足时，选最早创建的"]
        A4 --> A5["累计 ≥ L：匹配成功<br/>（累计 > H 为超额付款）<br/>累计 < L：部分付款，继续等"]
    end
    subgraph B["方向二：先到账，后建订单"]
        B1["新建订单"] --> B2["取这个客户回看时间内的未匹配到账，<br/>从最早的开始累计"]
        B2 --> B3{"累计达到 L 时<br/>是否不超过 H？"}
        B3 -->|"是"| B4["自动匹配，订单直接匹配成功"]
        B3 -->|"否，或一直达不到 L"| B5["不自动匹配，订单等待付款"]
    end
```

| 规则 | 说明 |
|---|---|
| 一笔到账 | 最多匹配一个订单；已经匹配的到账不会再被别的订单使用 |
| 一个订单 | 可以累计多笔到账 |
| 订单状态 | 等待付款 → 部分付款（累计 < L）→ **已完成**（L ≤ 累计 ≤ H）或 **超额付款**（累计 > H）；到了过期时间还没达到 L：累计为 0 的变成"已过期"，大于 0 的变成"部分付款（已过期）"，已经匹配的到账保留在这个订单上 |
| 过期后才到账 | 不再匹配已过期的订单，记为这个客户未匹配的到账，可以被以后的新订单匹配（在回看时间内），或者由商户手动匹配 |
| 手动匹配 | 商户后台和 API 都可以把同一个客户的未匹配到账**手动匹配**到他的某个订单，也可以**解除匹配**。订单状态按 L 和 H 重新计算；操作记进审计日志，并发订单匹配通知（标记"手动"） |
| 回调 | 每一笔到账都发**到账通知**；订单状态每次变化都发**订单匹配通知**（包括建单时就直接匹配成功的情况）。通知里带 `customer_id`、订单号、匹配到的到账列表和累计金额 |
| 提醒 | 同一个客户同时有两个金额接近的未完成订单时，系统只能按规则选择；开发者文档里提醒商户尽量避免 |

### 3.4 付款页面
- 显示订单金额、这个客户的地址和二维码、倒计时和状态。
- 如果打开时订单已经匹配成功（例如先到账后建单），直接显示"付款成功"。

## 4. 账本与手续费
| 规则 | 说明 |
|---|---|
| 余额 | 每个商户一个 USDT 余额，分为"可用"和"冻结"。余额按账本计算，**和资金有没有归集无关** |
| 收款费 | 入账时从到账金额中扣除。例如到账 1,000 USDT、费率 1%，可用余额增加 990 USDT |
| 付款费 | 提币时从余额中另外扣除。例如提币 1,000 USDT、费用 2 USDT，余额减少 1,002 USDT |
| 费率设置 | 每个商户分别设置收款费和付款费，每项都可以设"百分比"、"每笔固定金额"或者两者组合，也可以设最低收费 |
| 精度 | 6 位小数，内部按整数运算，不用浮点数；手续费不足最小单位的部分向上取整 |
| 账本 | 每一笔余额变动都写一条账本记录（入账、手续费、冻结、解冻、提币），**只追加，不修改** |
| 对账 | 每天核对一次：所有商户余额之和，是否等于"收款地址里还没归集的 USDT + 热钱包 + 冷钱包 − 已知的手续费支出"。不一致时发邮件通知 Amos |

## 5. 提币（付款）

```mermaid
stateDiagram-v2
    [*] --> pending: 商户提交（后台或 API）<br/>冻结 金额 + 付款费<br/>邮件通知 Amos
    pending --> cancelled: 商户取消（审核前）<br/>解冻
    pending --> rejected: Amos 驳回（填写原因）<br/>解冻
    pending --> signing: Amos 批准，在浏览器签名
    signing --> broadcast: 系统广播交易
    broadcast --> completed: 链上确认<br/>扣除冻结金额
    broadcast --> failed: 链上失败<br/>解冻，通知 Amos
    completed --> [*]
```

| 规则 | 说明 |
|---|---|
| 两种提币 | ① **商户提现**：提到商户在开户时声明、并经审核通过的钱包地址（开户表附录 B）。② **代付**：付给商户的客户，可以是任意地址 |
| 审核 | **每一笔都要 Amos 人工审核**，不论是后台还是 API 发起的。可以一次勾选多笔批量批准，只签一次名 |
| 通知 | 有新的提币申请时发邮件通知 Amos；1 分钟内的多笔合并成一封 |
| 处理时效（商户看到的说明） | "工作时间为东八区 8:00–23:00，工作时间内提交的提币申请 1 小时内处理；非工作时间提交的，顺延到下一个工作时间处理" |
| 余额不够 | 提交时直接拒绝 |
| 热钱包不够 | 保持"待审核"，审核页面提示 Amos 先归集 |
| 后台发起提币的安全要求 | 输入验证码 |
| API 发起提币的安全要求 | 请求签名 + **IP 白名单**。没有设置白名单的商户，不能用 API 提币 |
| 回调 | 状态每次变化时都发回调：已提交、已驳回、已取消、已广播、已完成、失败 |

## 6. 归集（运营后台）
- 页面列出所有有余额的收款地址，显示：商户、类型、USDT 余额、预估手续费、这一笔"用能量"还是"燃烧 TRX"、最后到账时间。
- 可以按商户、金额筛选和排序，**批量勾选，手动发起**。
- 归集时，系统先从热钱包给要归集的地址补手续费：热钱包质押了 TRX 的，借出能量；否则转一点 TRX。然后把 USDT 转走。两步都在一次签名里完成。
- 归集目标：默认归集到**热钱包**；也可以选 Amos 预先登记的**冷钱包**地址（只能选这一个）。

## 7. 签名与密钥
- **签名在 Amos 的浏览器里完成**，密钥不离开浏览器，系统只收到签好名的交易。
- 两把密钥：
  - **主助记词**：所有收款地址都由它推导，归集时用。
  - **热钱包私钥**：提币时用，归集前给收款地址补手续费也用它。
- 每一批操作输入一次密钥，签完立即清除，不做"记住密钥"。
- 签名前要再输入一次手机验证码。
- **初始化（只做一次）**：Amos 在浏览器里输入主助记词，浏览器只算出公钥（xpub）交给系统。系统用公钥生成收款地址。

**付款页面 `/pay/<订单号>/`（中英双语，付款方不需要登录）：**见 §3.4。

**运营后台 `/admin/` 新增：**
- 商户管理：开通、停用，设置手续费，**设置订单模式（§3.3 的五项）**。
- 客户（v6.1 新增）：按商户和客户标识搜索任意客户，查看他的地址、订单、到账和统计。

- 提币审核。
- 异常到账：不支持的币、低于最低金额。
- 对账：除了平台整体对账，每个商户下所有客户的收款合计必须等于这个商户的收款合计。
- 钱包设置：初始化公钥、热钱包地址、冷钱包地址、质押的能量情况。
- 系统状态：链上监控最后一次运行的时间、免费额度用量。

**开放 API（`/api/v1/`，每次请求都要签名）：**
| 接口 | 说明 |
|---|---|
| 新建或更新客户 / 查询客户 / 客户列表 / 客户统计 | 返回客户的永久地址；统计可以按时间段 |
| 创建订单 / 查询订单 / 订单列表 | 创建时 `customer_id` 必填；返回里带匹配状态（可能创建时就已匹配成功） |

| 回调：到账通知、订单匹配通知、提币状态 | Quick Come 签名，商户验证；失败自动重试 24 小时 |

**开发者文档 `/docs/`：**英文为主，同时提供中文；包含签名示例、回调验证示例、各接口示例、匹配规则说明。

| TP6-4 | 金额计算的边界：最小单位、向上取整、零费率、组合费率，都要有单元测试 | 已采纳 |
| TP6-7（v6.1） | 双向匹配的边界：累计正好等于 L、正好等于 H、比 L 少 1 个最小单位、比 H 多 1 个最小单位；多笔累计；两个方向同时发生（建订单的同时有到账进来）不能重复匹配；回看时间的边界；手动匹配后状态重新计算 | 已采纳，写进 AC-P20、P21 |
| TP6-5 | "系统不保存私钥"怎么验证：检查数据库、日志和请求记录里都没有助记词或私钥；检查签名页面不向任何地址发送密钥 | 已采纳，写进 AC-P11 |
| TP6-6 | 空状态：新商户的所有列表、余额都为 0 时的显示（v0.5.1 C32） | 已采纳，写进 AC-P15 |

## 10. 验收标准
| # | 验收标准 |
|---|---|
| AC-P1 | 开户审核通过后，系统自动开通商户账号，并给授权联系人发送设置密码的邮件；商户登录需要密码 + 验证码 |
| AC-P2 | 通过后台或 API 创建订单（客户标识必填）后，返回这个客户的地址和付款页面；订单模式关闭的商户不能创建订单 |
| AC-P3 | 同一个客户永远得到同一个地址；不同商户、不同客户的地址互不重复；转到客户地址的钱都记到这个客户名下 |
| AC-P4 | 往地址转 USDT 后，19 个确认后 **2 分钟内**（外部定时服务正常时）发出到账通知 |
| AC-P5 | 订单状态按 §3.3 流转（等待付款、部分付款、已完成、超额付款、已过期、部分付款（已过期）），订单匹配通知内容正确 |
| AC-P6 | 低于 1 USDT 的到账不入账、不匹配、不通知，但有记录；不支持的币出现在"异常到账"里 |
| AC-P7 | 收款费、付款费按 §4 计算，精确到 6 位小数；账本只追加；每天的对账结果正确，不一致时发邮件 |
| AC-P8 | 提币按 §5 的状态流转；提交时冻结，驳回或取消时解冻；余额不够时拒绝；没有 IP 白名单的商户不能用 API 提币 |
| AC-P9 | 每笔提币申请都会发邮件通知 Amos（1 分钟内的合并成一封）；商户页面显示 §5 规定的处理时效说明 |
| AC-P10 | 归集页面按 §6 显示并支持筛选、批量勾选；一次签名完成"补手续费 + 转出 USDT"；归集只能转到热钱包或登记的冷钱包 |
| AC-P11 | **安全**：<br/>① 数据库、日志、请求记录里都不存在助记词或私钥。<br/>② 签名页面不向任何地址发送密钥。<br/>③ API 请求没有签名、签名错误或时间戳过期时，返回 401。<br/>④ 回调带签名。<br/>⑤ 一个商户不能读取或操作另一个商户的任何数据 |
| AC-P12 | 回调失败时自动重试（1 分钟、5 分钟、30 分钟……最多 24 小时），后台可以手动重发 |
| AC-P13 | 付款页面在 375、768、1280 三种宽度下都能正常使用，中英双语；倒计时和状态实时更新 |
| AC-P14 | 开发者文档覆盖全部接口，签名示例可以直接运行并通过 |
| AC-P15 | 空状态：新商户的余额、订单、交易、提币都显示"0"或"暂无"（v0.5.1 C32） |
| AC-P16 | 测试环境（Nile 测试网）走通：初始化 → 客户收款（不建订单）→ 先建订单后到账 → 先到账后建订单 → 归集 → 提币。生产上线后，用 1 USDT 做一次真实的收款和提币冒烟检查 |
| AC-P17 | 系统状态页面显示链上监控最后运行的时间；超过 5 分钟没有运行时，发邮件通知 Amos；免费额度用量达到 70% 时发邮件提醒 |
| AC-P18 | 官网、开户（v1 到 v5）的全部验收项回归通过 |
| AC-P19（v6.1） | 商户后台和运营后台都能按客户查看地址、订单、到账、代付，按时间段统计收款合计、笔数、手续费，导出客户对账单；运营后台可以跨商户搜索客户；对账时每个商户下客户收款合计等于商户收款合计 |
| AC-P20（v6.1） | 双向匹配按 §3.3：先建订单后到账、先到账后建订单（只在回看时间内）都能自动匹配；多笔累计；L、H、过期时间、回看时间按 Amos 在运营后台设置的值生效，修改后只影响之后的匹配 |
| AC-P21（v6.1） | 手动匹配、解除匹配只能在同一个客户内部操作；操作后订单状态重新计算，发订单匹配通知，并记进审计日志；匹配和解除匹配都不改变商户余额 |

## 11. 明确不做
- 不做 Ethereum、BSC 等其他网络（下一版再做）。
- 不做能量租赁、批量转账合约。
- 不做法币换算和法币出入金。
- 不做一个商户多个登录账号和权限分级。
- **不对外开放**：朋友使用期间不在官网公开宣传收付款功能，对外开放前先处理牌照并迁移服务器（RK-v6-1）。
