## 3. 质量结论（来自《v1-测试报告》）
- **验收标准：** AC1 到 AC11 全部**实际执行并通过**；AC12（HTTPS）要等生产环境部署后，用 `verify.sh` 验证。

- **缺陷：** 发现 3 个缺陷和 2 条建议，**全部已修复并回归通过**，没有遗留问题。
  - BUG-01（严重）：表单提交成功后，表单仍然显示。
  - BUG-02（一般）：前端没有校验电话格式。
  - BUG-03（严重，会阻断部署）：生产 Nginx 配置不兼容 Ubuntu 24.04 自带的 Nginx 1.24。

## 4. ⚠️ 需要 Amos 确认或提供的事项

### 4.1 部署前必须提供（详见《部署方案》§1）
1. 新加坡的 Ubuntu 24.04 服务器，以及一个免密 sudo 的 SSH 部署账号。
2. 购买域名 `quickcomepay.com` 和 `getquickcome.com`，并托管到 Cloudflare。
3. 发信用的 SMTP 账号，以及接收线索的邮箱地址。
4. 执行部署的方式：
   - (a) 由您或您的运维同事按《部署方案》§3 执行（推荐）。
   - (b) 给我一个临时部署账号，由我执行。

### 4.2 上线前需要确认属实的内容（PM 起草的文案，需要业务方确认）
PM 按照"不脑补"的原则起草了文案，但下面这些是**对产品能力的描述**，PM 无法自行核实，请 Amos 逐条确认，不属实的删掉或修改：
- **安全与合规页：**
  - 每个账户开通前都做企业认证（KYB）。
  - 所有入账款项都做风险筛查，存在疑点的款项可能暂缓处理。
  - 账户支持双重验证和基于角色的权限管理。
- **首页和工作原理页：**
  - 收款请求可以关联订单编号。
  - 款项会自动记录到对应订单。
  - 支持 TRON、Ethereum 以及其他主流公链。
- **联系页：** "通常在一个工作日内回复"。
- **邮箱：** `sales@quickcomepay.com`、`privacy@quickcomepay.com` 需要在买下域名后实际开通。
- **服务主体：** 页脚、隐私政策、服务条款里的服务主体目前写的是"Quick Come"，是**占位用的**。请提供正式的公司主体名称。
- ⚠️ **隐私政策和服务条款是 PM 起草的通用版本，不是法律意见。上线前建议由法务审核**，尤其是您的目标市场（新加坡、欧盟等）对个人数据保护的具体要求。

### 4.3 可选决定（不影响上线）
- **手机端常驻"预约演示"按钮：** 目前放在菜单里，符合 AC4。是否在手机首屏增加一个常驻按钮，作为 v2 的候选优化？
- **邮件发送失败的自动重发：** 技术债 R2。目前的做法是记录日志，并提供手动补发脚本。是否在 v2 里做成自动重发？
