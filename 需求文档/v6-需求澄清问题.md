## 1. "收付款"要做哪些事
| 功能 | 做什么 | 谁用 |
|---|---|---|
| **收款** | 商户创建收款单（金额、币种、网络、有效期）→ 系统生成付款页面和收款地址 → 付款方转账 → 链上确认后自动入账，并通知商户 | 商户、付款方 |
| **结算 / 付款** | 把商户收到的钱，打到商户在开户时声明过的钱包地址（附录 B 的钱包）；以后也可以支持"代商户付款给第三方" | 商户、Amos 审核 |
| **商户后台** | 登录（密码加验证码）、收款单列表、交易明细、余额、对账导出、通知设置 | 商户 |
| **运营后台** | 在现有的审核后台里，增加商户管理、交易查询、付款审批、手续费设置 | Amos |
| **对接（可选）** | 给商户开放 API 和回调（Webhook），让商户自己的系统能自动下单、自动收到到账通知 | 商户的技术人员 |

## 2. 最关键的决定：谁来"拿着钱"（托管模式）

三种做法的区别，在于资金在链上**进入谁控制的钱包**：

```mermaid
flowchart TB
    subgraph A["方案 A：非托管（钱直接进商户自己的钱包）"]
        A1["付款方"] -->|"USDT"| A2["商户自己的钱包"]
        A3["Quick Come"] -.->|"只做：生成收款单、<br/>盯链上到账、通知"| A2
    end
    subgraph B["方案 B：自己托管（钱先进 Quick Come 的钱包）"]
        B1["付款方"] -->|"USDT"| B2["Quick Come 控制的钱包<br/>（我们保管私钥）"]
        B2 -->|"结算"| B3["商户的钱包"]
    end
    subgraph C["方案 C：接入持牌合作方（钱进合作方托管）"]
        C1["付款方"] -->|"USDT"| C2["持牌合作方<br/>（托管、合规由它负责）"]
        C2 -->|"结算"| C3["商户的钱包"]
        C4["Quick Come"] -.->|"调用合作方 API：<br/>下单、查询、结算"| C2
    end
```

| | A 非托管 | B 自己托管 | C 接入持牌合作方 |
|---|---|---|---|
| 资金安全责任 | 在商户自己 | **全部在 Quick Come**（私钥、热钱包、冷钱包） | 在合作方 |
| 牌照要求 | 最低（可能仍需法律确认） | **最高**：在新加坡通常需要 MAS 的数字支付代币（DPT）牌照，其他地区另有要求 | 牌照由合作方承担，Quick Come 可能需要代理或合作协议 |
| 能不能做"余额、结算、代付" | 不能，钱不经过我们 | 能 | 能（看合作方的能力） |
| 开发量 | 小（几周） | **很大**：钱包、私钥管理、账本、对账、风控、链上监控 | 中：对接 API、账本、商户后台 |
| 平台 | 可以继续用 Vercel | 需要专门的服务器和密钥管理设备，**不适合 Vercel** | Vercel Pro 加数据库，基本可行 |
| 上线速度 | 最快 | 最慢（取决于牌照） | 取决于合作方的对接和签约 |

**PM 的建议：优先 C，没有合作方就先做 A。不建议现在做 B。**
- B 意味着 Quick Come 要保管客户的钱。这需要牌照、资金安全体系和审计，**不是一次软件迭代能解决的**。
- Paypaz 本身就是稳定币支付公司。**如果 Paypaz 可以作为底层的持牌合作方**，C 是最顺的：Quick Come 专注商户体验，资金、托管、合规用 Paypaz 现成的能力。这一点需要你确认（问题 A1），我不做推断。

## 8. 第二轮问题
自己托管加上不买服务器，会带出三个必须先定下来的技术问题：**私钥放在哪里（F）、谁来盯着区块链看有没有到账（G）、钱从收款地址怎么归集（H）**。

### F. 私钥与资金安全（最关键）
| # | 问题 | 建议默认 |
|---|---|---|
| **F1** | 私钥放在哪里？<br/>(a) 加密后放进 Vercel 的环境变量，由系统自动签名<br/>(b) 系统只负责生成地址（只用公钥），签名交给 Amos 自己电脑上运行的"签名工具"，每次需要 Amos 在线确认<br/>(c) 使用第三方的托管签名服务（例如 MPC 钱包服务） | **(a) + 严格限额**：<br/>收款地址的私钥由一个"主种子"推导，主种子加密后放在 Vercel（只作用于生产）；热钱包只保留少量资金，超出部分自动转到冷钱包。**系统被攻破时，最多损失"还没归集的钱 + 热钱包里的钱"。**<br/>朋友使用期间，这个风险可以控制；对外开放前迁移到阿里云或 AWS 时，改用 KMS 或 MPC |
| **F2** | 热钱包的上限是多少？ | **每个币种 2,000 USDT**。超过的部分自动转到冷钱包 |
| **F3** | 冷钱包由谁、用什么保管？ | Amos 用**硬件钱包**（例如 Ledger）保管。冷钱包的地址写死在系统里，系统**只能往冷钱包转钱，不能从冷钱包转出** |
| **F4** | 主种子（助记词）怎么备份？ | Amos **离线手抄两份**，分开存放，不存任何电子设备。丢失主种子等于丢失所有收款地址里的钱 |

### G. 链上监控（怎么知道钱到了）
| # | 问题 | 建议默认 |
|---|---|---|
| **G1** | Vercel 免费版的定时任务每天只能跑一次，没法每分钟检查链上。用什么办法？<br/>(a) 区块链数据服务的**推送通知**（有到账时它主动通知我们）<br/>(b) 免费的外部定时服务（例如 cron-job.org），**每分钟**调用一次我们的检查接口<br/>(c) 两者都用 | **(c)**：以 (a) 为主，(b) 作为兜底。每分钟一次的兜底检查，保证最晚 1 到 2 分钟内发现到账 |
| **G2** | 用哪家区块链数据服务？（需要 Amos 注册账号，免费档） | **TRON：TronGrid**（官方，免费 API Key）；**Ethereum：Alchemy**（免费档支持地址到账推送）。按 C27，注册时请截图确认免费档 |

### H. 归集与手续费
| # | 问题 | 建议默认 |
|---|---|---|
| **H1** | 钱到了收款地址后，怎么归集到热钱包？ | **到账后自动归集**。TRON 链上转 USDT 需要消耗 TRX（手续费），系统先从热钱包给收款地址转一点 TRX，再把 USDT 转走；Ethereum 同理需要 ETH。**金额很小的（低于 10 USDT）先不归集**，攒够了再归集，避免手续费比金额还高 |
| **H2** | 归集和提币产生的链上手续费（TRX、ETH）谁出？ | **Quick Come 出**，从手续费收入里覆盖。定价时考虑进去：Ethereum 的手续费明显比 TRON 高 |
| **H3** | 这次支持哪些网络？ | **先只做 TRON（USDT-TRC20）**。Ethereum 的归集手续费高、逻辑更复杂，**放到下一版**。以后再加 BSC、Polygon 等 |

### I. 两种收款方式的细节
| # | 问题 | 建议默认 |
|---|---|---|
| **I1** | "永久分配"的地址分成哪几类？ | 每个商户有两类地址池：<br/>① **订单地址池**：给订单收款用。一个地址同一时间只服务一个未完成的订单；订单结束后，地址回到这个商户自己的池子，**不会给别的商户用**。<br/>② **userid 地址**：给无订单收款用。每个 userid 一个地址，永久不变 |
| **I2** | 订单收款：客户付的金额和订单不一致时怎么办？ | 按第一轮 B3：误差在 **±0.5%** 以内视为匹配成功；付少了标记"部分付款"，付多了标记"超额付款"，都发回调，交商户处理；订单过期后到账，发"到账通知"，但不匹配订单 |
| **I3** | 订单有效期？ | 默认 **30 分钟**，商户创建订单时可以自己设（5 分钟到 24 小时） |
| **I4** | 无订单收款：有最低入账金额吗？ | **有，默认 1 USDT**。低于这个金额的，视为垃圾转账，不入账也不通知，但记录下来 |
| **I5** | 充值后多久可以用？ | TRON 按第一轮 B4：**19 个确认**（大约 1 分钟）后入账并通知 |

### J. 提币（付款）
| # | 问题 | 建议默认 |
|---|---|---|
| **J1** | 提币有哪几种？ | ① **商户提现**：把自己的余额提到自己声明过的钱包（开户表附录 B），在后台操作。<br/>② **代付**：商户通过 API 或后台，把钱付给**商户的客户**（任意地址），也就是"提币场景" |
| **J2** | 代付给任意地址，风险最高。要不要人工审核？ | **分级处理**：单笔 ≤ 1,000 USDT，而且当天累计 ≤ 5,000 USDT 的**自动放行**；超过的进入"待审核"，由 Amos 在后台批准。每个商户的限额可以单独调整 |

| **J4** | 余额不够、热钱包不够时怎么办？ | 商户余额不够：直接拒绝。热钱包不够：进入"排队中"，通知 Amos 从冷钱包补充，补够后自动继续 |

### K. 手续费和对账

| **K1** | 手续费怎么设置？ | 每个商户分别设置"**收款费**"和"**付款费**"，每项都可以选"百分比"或"每笔固定金额"，也可以两者都设（例如 0.5% + 1 USDT）。可以设最低收费 |

## 10. 第三轮问题（最后一轮）

### 一图看懂：Amos 手动签名时，密钥怎样才能"不经过系统"

```mermaid
sequenceDiagram
    participant A as Amos 的浏览器
    participant S as Quick Come 系统（Vercel）
    participant T as TRON 网络
    Note over A,S: 初始化（只做一次）
    A->>A: 输入主助记词，在浏览器里算出"公钥"（xpub）
    A->>S: 只把公钥交给系统
    S->>S: 用公钥生成收款地址（系统能生成地址，但动不了钱）
    Note over A,T: 每次归集或提币
    S->>A: 待签名的交易清单（金额、地址、手续费）
    A->>A: 输入密钥，在浏览器里签名<br/>（密钥不离开浏览器，用完立即清除）
    A->>S: 只提交"已签名的交易"
    S->>T: 广播交易，记录交易号
    T-->>S: 链上确认 → 更新状态、通知商户
```

### P. 密钥与签名
| # | 问题 | 建议默认 |
|---|---|---|
| **P1** | 签名在哪里完成？<br/>(a) **在 Amos 的浏览器里签名**：密钥不离开浏览器，系统只收到签好名的交易<br/>(b) 密钥发给服务器，由服务器签名（密钥不保存，但会经过服务器） | **(a)**。即使系统被攻破，攻击者也拿不到密钥。页面沿用现在的严格安全策略（CSP），禁止加载任何外部脚本 |
| **P2** | 需要哪几把密钥？ | **两把**：<br/>① **主助记词**：所有收款地址都由它推导，归集时用来签名。初始化时，只在浏览器里算出公钥交给系统。<br/>② **热钱包私钥**：用来提币，以及归集前给收款地址补 TRX 手续费。<br/>两把都由 Amos 离线保管，系统都不保存 |
| **P3** | 每次操作都要输入密钥吗？ | **每一批操作输入一次**：例如勾选 20 笔提币，输入一次密钥，全部签名；签完立即从浏览器内存里清除，关闭页面也会清除。**不做"记住密钥"** |
| **P4** | 输入密钥前，还要再验证一次身份吗？ | **要**：签名前再输入一次手机验证码，防止别人趁 Amos 离开电脑时操作 |

### Q. 归集
| # | 问题 | 建议默认 |
|---|---|---|
| **Q1** | 归集页面显示什么？ | 列出**所有有余额的收款地址**：商户、类型（订单 / userid）、USDT 余额、预估手续费、最后到账时间。可以按商户、金额筛选和排序，批量勾选 |
| **Q2** | 归集要消耗 TRX（手续费），而且不便宜：在 TRON 上从一个地址转出 USDT，通常要消耗十几到二十几个 TRX，具体以链上实际为准。怎么处理？ | 页面上**显示每个地址的预估手续费**，并提示"手续费高于余额的某个比例"的条目。归集时，系统先用热钱包给这些地址**补 TRX**，再转走 USDT，一次签名完成两步。以后可以接入"能量租赁"来降低成本 |
| **Q3** | 归集到哪里？ | **默认归集到热钱包**。也可以选择直接归集到冷钱包（冷钱包地址由 Amos 预先登记，只能选这个地址） |

### R. 提币审核
| # | 问题 | 建议默认 |
|---|---|---|
| **R1** | 可以一次批准多笔提币吗？ | **可以**：勾选多笔，输入一次密钥，批量签名 |
| **R2** | 审核时能看到什么？ | 商户、金额、手续费、收款地址、提币方式（后台或 API）、这个地址以前有没有收过款、商户当前余额。可以**批准**或**驳回**（驳回时填写原因，冻结的金额退回商户余额） |
| **R3** | 商户提交提币后，钱怎么处理？ | 提交时**立即冻结**"提币金额 + 付款手续费"；在 Amos 批准之前，商户可以**取消**；驳回或取消时解冻。提币状态变化时发回调给商户 |
| **R4** | 商户看到的处理时间怎么写？ | 显示"**人工审核，通常在 24 小时内处理**"。具体时效请你来定 |
| **R5** | 邮件通知：每天 1 万笔的规模下，提币申请可能很多，而 QQ 个人邮箱每天的发送数量有上限。怎么办？ | **每笔申请都通知，但 1 分钟内的多笔合并成一封邮件**。后台同时显示"待审核"数量。发送量接近上限时，建议换成品牌邮箱和发信服务（域名买好后） |

### S. 其他资产与异常
| # | 问题 | 建议默认 |
|---|---|---|
| **S1** | 有人往收款地址转了不支持的币（例如别的代币），或者直接转 TRX，怎么办？ | **不入账**，在后台的"异常到账"里列出，由 Amos 人工处理 |
